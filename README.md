# **Money Management Application**

## Personal Proposal

This application will help users manage their personal finances by creating a profile, setting a monthly budget, and tracking both payments and earnings. Users will be able to add and delete payments or earnings with type and amount, set the budget for the current month's payment, and view spending progress through percentages. At the end of each month, the application will reset the budget, store the old records, and provide a breakdown of spending and earnings by category to give users a clear picture of their money habits.

The main users of this application will be students and young adults who are starting to live on their own and want to learn effective money management skills. This project is of personal interest to me because I recently began living independently on campus, away from my family. I want to train myself in budgeting, identify unnecessary expenses, and save toward future goals such as travel. Building this application will not only improve my programming skills but also help me practice responsible financial planning in my own life.


## User Stories  

- As a user, I want to be able to create a profile with my name and starting amount.  
- As a user, I want to be able to add payments with type, amount.
- As a user, I want to be able to delete payments with index select.    
- As a user, I want to be able to view my list of payments.  
- As a user, I want to be able to add earnings with type, amount.  
- As a user, I want to be able to delete earnings with index select.
- As a user, I want to be able to view my list of earnings.  
- As a user, I want to be able to view the amount of my budget left.  
- As a user, I want to be able to end this record and restart for a new record.  
- As a user, I want to be able to view the breakdown of my spending and earnings by category.
- As a user, I want to be able to save my financial data to a file so that I can keep all my earnings, payments, and budget information for future sessions.
- As a user, I want to be able to load my previously saved financial data from a file so that I can continue managing my budget and earnings exactly where I left off.  


# Instructions for End User
- By opening the Earning or Spending tabs on the left sidebar, you can see the panel that shows the Xs that have previously been added to the Y.  A summary of all the items (earnings or purchases) that have already been added to the user profile is displayed on each tab.

- The first necessary action for the user story "adding multiple Xs to a Y" can be generated by selecting the Add button under the Earning or Spending tab.  This opens the Add Panel, where you can add a new X (your earnings or purchases) to the Y (the user) by choosing a category and entering an amount.

- The second necessary action for the user story "deleting multiple Xs to a Y" can be generated by selecting the Delete button under the Earning or Spending tab.  This opens the Delete Panel, where you can choose an already-existing X and delete it from the user's data.

- You can find my visual component by looking at the Main Menu tab. At the top of the screen is a custom pastel banner logo called "BlossomBudget."  The project's visual component is this banner.

- By opening the Main Menu tab and selecting the Save Record button, you can store the current state of your app.  This creates a JSON file with the user's earnings, spendings, and profile details.

- By opening the Main Menu tab and selecting the Load Record button, you can reload the state of my program.  The user's data is restored into the GUI by reading the saved JSON file.

# Phase 4: Task 3

If I had more time to work on this project, one refactoring I would apply is to reduce duplication between the EarningTab and SpendingTab classes. Currently, both tabs contain very similar logic for displaying category summaries, handling add and delete panels, and refreshing the UI after changes. I would refactor this by introducing an abstract superclass such as AbstractTransactionTab that encapsulates the shared behavior (for example, building summaries, toggling add/delete panels, and refreshing lists). EarningTab and SpendingTab would then extend this class and only provide category-specific details. This change would reduce duplicated code, make the system easier to maintain, and minimize errors when modifying shared functionality.

Another refactoring I would consider is improving the visual design and structure of the user interface. Currently, many buttons share similar styles but are created independently in each tab. With more time, I would refactor the button creation into reusable helper methods or utility classes so that all buttons share consistent styling (such as font, color, and size). I would also replace some plain-text buttons with more visual signals, such as icons or color-coded buttons (for example, red for delete and green for add), to improve usability and make the interface more intuitive and visually appealing. This refactoring would enhance the overall user experience without changing the core functionality of the application.
